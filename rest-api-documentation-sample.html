Change Management REST API

Use Change Management to plan, schedule, implement, and manage changes to the technology environment in your organization. For example, plan, schedule, and manage data migration tasks.

The Change Management API is organized around REST. It uses JSON for requests and responses, and standard HTTP status codes. Authenticate by sending your API key in the Authorization header.

Base URL: https://api.example.com/v1

Create a change request

POST/change

Creates a new change request.

Header parameters

Request body parameters

NameTypeRequiredDescription
book_idsummarystringYesSummary for the change request.
expandimpactintegerNoImpact of the change on the service level of the affected business processes.

The following are the supported values:

  • 1000: Extensive/Widespread
  • 2000: Significant/Large
  • 3000: Moderate/Limited
  • (Default) 4000: Minor/Localized
book_idurgencystringNoUrgency measures how soon the change will significantly impact the business.

For example, a high-impact change may have low urgency if the impact is not expected to affect the business in the near future.

The following are the supported values:

Example request

curl -X GET "https://api.example.com/v1/books/bk_123?expand=author" \
  -H "Authorization: Bearer YOUR_API_KEY"

Example response

{
  "id": "bk_123",
  "title": "The Pragmatic Writer",
  "isbn": "978-0-00-000000-0",
  "available": true,
  "author": { "id": "au_45", "name": "Alex Rivera" }
}

Response codes

CodeMeaning
200The book was returned.
401The API key is missing or invalid.
404No book exists with that ID.
429Too many requests. Retry after the time in the Retry-After header.

Create a book

POST/books

Adds a book to the catalog. Send title and isbn in the JSON body. A successful call returns 201 with the new book.
